# 바닐라코 동남아 Shopee 영어 AI 진행 콘텐츠 설계

작성일: 2026-10-02 KST · 상태: Architect 및 Critic 독립 검토 통과, 계획 수립 완료 · 현재 범위: 계획 수립. 실제 영상 생성·앱 구현·공개 방송은 아직 실행하지 않았다.

## 1. 목표, 성공 기준, 결정이 필요한 경계

**추천안은 영어 음성을 먼저 승인한 뒤 고정 진행자의 짧은 립싱크 영상으로 제작하고, 혜택·구성 설명과 브랜드 원본 증거를 편집하는 방식이다.** AI는 구매 선택과 프로모션 이해를 돕고, 발색·텍스처·실제 시연·효능 증거는 승인된 원본으로 보여준다. 자연스러운 영어 발화와 입 움직임이 최우선 품질 기준이다.

사용자가 원하는 24시간 운영은 세 목표로 나눈다.

| 목표 | 계획의 산출물 | 현재 확정 범위 |
|---|---|---|
| 콘텐츠 제작 | 12개 테마 × 실제 서사가 다른 2개 버전 × 6분 = 24편, 합계 144분의 편집본 | 단계별 제작 제안. 공통 원본 증거가 일부 재사용되므로 모든 프레임이 고유한 144분이라는 뜻은 아님 |
| 연속 재생 검증 | 144분 편성을 10번 재배열한 1,440분/24시간 로컬 리허설 | 송출기·오퍼 갱신·장애 복구 검증. 24시간 신규 콘텐츠가 아님 |
| 공개 Shopee Live | 실제 국가·판매 계정에 허용되는 AI/라이브 형식과 감독 운영 | 승인 범위와 세션 조건 미확인. 로컬 리허설 통과와 별도 게이트 |

편성 변경이나 서사 변형이 녹화·반복 콘텐츠 제한을 우회하는 방법은 아니다. 완전히 새로운 24시간 분량이 필요하면 6분 기준 240편 규모의 별도 프로젝트로 산정한다.

**계획상 성공 기준:** 동일 영어 음원 비교로 채택 가능한 엔진·호스트·음성 각 1개를 결정할 수 있고, 오퍼가 바뀌어도 설명·화면·상품 카드가 모순되지 않으며, 24시간 로컬 재생에서 오류와 복구를 증명할 수 있는 제작·운영 설계를 남긴다. 이 문서와 [뷰티 문법](banila-shopee-ai-live_beauty-grammar_v1.md), [검증 명세](banila-shopee-ai-live_test-spec_v1.md)를 일치시키고 검토를 마치면 현재 작업을 종료한다. 구현이나 공개 방송으로 자동 전환하지 않는다.

첫 판매국은 미정이다. **PH를 영어 청취 품질 실험의 계획 가정**으로 두고 SG를 대안으로 둔다. 이는 해당 국가의 공개 AI 방송 허용이나 영어만으로 모든 동남아 시장을 운영할 수 있다는 판단이 아니다.

## 3. Shopee 공개 운영 게이트

**SG/PH/MY에서는 사전 녹화물을 무인으로 반복하는 방송을 기본 허용 경로로 두지 않는다.** SG는 prerecorded/replay를 제한하고, PH는 정지·사전 녹화·호스트/상호작용 부재·대부분 녹화 광고 등의 저품질 사례를 열거한다. MY도 장시간 녹화 및 실시간 상호작용 없는 반복을 문제로 다룬다. [SG 위반 안내](https://help.shopee.sg/portal/4/article/134853), [PH 위반 안내](https://help.shopee.ph/portal/4/article/132230), [MY 녹화 정책](https://help.shopee.com.my/portal/10/article/148685)

ID는 Shopee가 심사·승인한 AI 재방송 영상의 명시적 예외가 있지만, 대부분을 Bahasa Indonesia로 진행해야 하는 별도 조항이 있다. 영어판을 그대로 ID로 확대하지 않는다. VN은 일부 짧은 설명 영상의 예외를 확인했으나 seller 적용 범위와 AI 조건을 더 확인해야 한다. TH는 이번 조사에서 관련 공식 본문을 확보하지 못했다. [ID 규정 §9(m), §10(f)](https://help.shopee.co.id/portal/4/article/130278), [VN 품질 안내](https://help.shopee.vn/portal/10/article/141462)

AI 표시, 사람의 텍스트 댓글 응대, 영상 수 증가만으로 녹화 제한이 해소되지 않는다. AI 전용 표시·승인 가이드의 존재와 상세 본문을 확인한 범위도 구분한다. 실제 계정에 대해 다음 증거를 모은 뒤 **허용된 형식만** 공개한다.

| 게이트 | 필요한 증거 | 미확인 시 경로 |
|---|---|---|
| 국가·계정·콘텐츠 형식 | 최신 공식 가이드 및 공식 담당 경로의 서면 확인: AI 모델/호스트/영상/캠페인 승인 단위, 녹화·반복·표시·실제 상호작용 조건 | 콘텐츠 제작·로컬 검증까지만 진행 |
| 원본 삽입 | 허용 길이·빈도·호스트 유지 조건과 콘텐츠 권리 | 원본 파일은 보관하되 Live 삽입 미확정 |
| PC/송출 | 실제 계정의 PC/OBS/RTMP 권한, 규격, 세션 길이·키 수명·종료/재시작 조건 | 24시간 단일 세션·자동 재시작을 보장하지 않음 |
| 거래 기능 | 실제 상품 pin·쿠폰·댓글·캠페인 기능과 승인된 연동 범위 | 운영자가 Shopee 콘솔에서 수행 |

SG 약관은 자동 스크립트의 정보 수집·Live 상호작용을 제한한다. 댓글 스크래핑, 비공식 API, 브라우저 자동 pin/쿠폰 조작을 기본 구조에 넣지 않는다. 송출키와 인증정보는 승인된 경로로만 취급한다. [SG 약관 §4.1(g)](https://help.shopee.sg/portal/4/article/181506)

녹화 중심 Live가 허용되지 않으면 **실시간 사람 호스트 + AI 대본·진행 보조 + 허용된 짧은 원본 증거**로 공개 경로를 바꾸고, 사전 제작본은 적합한 비Live placement에 활용한다. 승인된 실시간 AI 형식이 있다면 별도 realtime 엔진과 실제 상호작용을 검증한다. 오프라인 HeyGen/Sync 품질 점수로 realtime 제품을 통과시킬 수 없다. 24시간 운영이 허용되더라도 감독 교대·콘솔 작업·세션 인계가 필요하다.

## 4. RALPLAN-DR와 기술 선택

**원칙 3개:** ① 영어 발화와 입 움직임을 먼저 승인한다. ② 상품 사실·오퍼·시연은 추적 가능한 원본을 사용한다. ③ 제작 가능성과 플랫폼 공개 운영 권한을 별도로 검증한다.

**선택 기준 상위 3개:** 자연스러운 영어와 얼굴 유지 / 오퍼 변경의 정확성·비용 / 국가별로 허용되는 감독·상호작용 운영.

| 대안 | 장점 | 실제 비용·제약 | 사용 판단 |
|---|---|---|---|
| A. Hosted avatar 제작: HeyGen IV 또는 eligible V | 외부 영어 음원으로 아바타 영상 생산, API·비동기 작업 경로 | V는 적격 digital twin look 필요. 동의·계정 권한·플랜·데이터 조건 확인. 품질 미검증 | MVP 비교 후보 |
| B. 원본 진행자 영상 + 자체 통제 제작 파이프라인 + Sync | 승인 원본의 제스처와 master audio를 관리하고 구간별 입 움직임을 수정 | 얼굴이 말하는 자연스러운 소스가 필요. 원본 촬영·편집·권리 비용. 모델은 외부 서비스이며 자체 ML 모델 구축이 아님 | MVP 비교 후보. sync-3 이미지 경로도 별도 비교 가능 |
| C. 실시간 사람 또는 승인된 realtime AI 진행 | 실제 질문·거래 상황에 반응하는 공개 Live 경로 | 사람 운영비 또는 realtime 품질·지연·안전·연동 검증을 별도로 부담 | 공개 정책 결과에 따라 필요한 분기 |

A/B는 사전 제작 엔진의 대안이고 C는 방송 형식의 대안이다. A/B를 선택했다고 C 없이 공개 녹화 반복이 허용되는 것은 아니다. 처음부터 자체 모델 학습·GPU 운영을 포함하는 접근은 면허·상업 사용·품질·운영비 근거가 부족해 초기 범위에서 제외한다. 이는 장기 대안을 영구 폐기한다는 뜻은 아니다.

**조건부 선택:** 영어 master audio를 먼저 고정한 다음 A/B의 공정한 비교를 수행하고 통과한 한 경로를 기본 생산 엔진으로 선택한다. 실패할 때 다른 후보로 전환할 수 있도록 manifest와 음원을 공급사에 종속시키지 않는다. HeyGen V는 `supported_api_engines`에 `avatar_v`가 있는 eligible digital twin에만 사용한다. [HeyGen Audio to Video](https://developers.heygen.com/audio-to-video), [Avatar V](https://developers.heygen.com/avatar-v), [Sync sync-3](https://sync.so/docs/models/sync-3), [Sync 입력 caveats](https://sync.so/docs/models/lipsync)

## 5. 자연스러운 영어와 립싱크 제작 기준

호스트 1명, 음성 1개, 얼굴·의상·조명·카메라 높이·배경을 고정한다. 영어는 목표 국가 청취자가 편하게 이해하는 명료한 톤으로 만들고, 과한 판매 고음·쉼 없는 낭독·인위적 사투리를 피한다. 영어 진행자가 본인 사용감이나 현지인 정체성을 주장하지 않는다.

**제작 순서:** 승인 사실 → 짧은 영어 문장 → 발음 사전/숫자 읽기 → 음성 검수 → master WAV 고정 → 15–35초 독립 shot 렌더 → 입·얼굴 검수 → 승인 원본 삽입 → 자막·혜택 화면 편집 → 최종 오퍼 일치 검사. 문장과 생각의 단위로 자르며 단어 중간에서 잘라 이어 붙이지 않는다. 최종 편집에서 말속도만 바꾸거나 승인 음원을 교체해 싱크를 깨뜨리지 않는다.

### 두 공급사 비교 실험

1. 음성 후보 2–3개를 먼저 비교해 master를 고정한다. 립싱크 기본 시험은 인사 20초·구성 15초·용량 25초·가상 쿠폰 35초·FAQ 30초·연결 문장 45초의 6개 장면이다. /p b m f v/·미소 후 발화·쉼을 포함한다. 합계 170초, 두 엔진이면 340초 약 5.67분이며 추가 take/입력 트랙은 별도다. 45초는 스트레스 시험이고 생산은 15–35초를 기본으로 한다. 테스트 숫자는 TEST 표시를 유지하며 실제 오퍼로 사용하지 않는다.
2. 이미지 트랙은 같은 승인 portrait와 같은 master audio로 **HeyGen IV ↔ Sync sync-3**를 비교한다. 동의받은 실인물 소스가 있다면 같은 호스트·음원으로 **HeyGen eligible V digital twin ↔ Sync 영상 경로**를 추가 비교한다. 학습/입력 구조가 다르므로 완전 동일 영상 입력 실험이라고 부르지 않는다. lipsync-2-pro는 talking-motion 원본이 있을 때만 시험한다.
3. 공급사 이름을 숨기고 순서를 무작위로 섞어 영어 평가자 5명, 최소 3명은 목표 국가 영어 사용자가 평가한다. 음성·입 움직임·얼굴 유지·표정·반복 피로를 분리 기록한다. 브랜드 검수자는 혜택·제품명·발음을 별도 판정한다.
4. **제안 채택 목표 AC-LIP:** 음성 자연스러움과 립싱크 각각 평균 ≥4.2/5, 5명 중 4명 이상 채택 가능. 핵심 발음·혜택 숫자·시각적 중대 결함 0건. 2명의 판독자가 합의한 발음 기준점 clip당 ≥5개, 전체 ≥30개의 수동 frame 판독 p95 절대 A/V 오차 ≤80ms. 합의 불가 지점은 통과로 계산하지 않는다. 얼굴 drift·지속적 어긋남·치아 flicker를 점수로 상쇄할 수 없다.
5. 6분 편집본과 압축된 실제 재생본을 다시 보고, 좋은 한 클립으로 장편 품질을 추정하지 않는다. 통과 엔진·실측 재생성 배수·채택 초수·리뷰 timestamp를 기록한다.

위 수치는 내부 제안 기준이며 공급사 보장이나 이미 달성한 성능이 아니다. 자세한 판독 표본과 hard sentinel은 [검증 명세](banila-shopee-ai-live_test-spec_v1.md)에 고정한다. 통과하지 못하면 호스트/음성/shot 조건을 수정해 재시험하고 라이브러리 대량 제작을 시작하지 않는다.

## 6. 바닐라코의 프로모션 중심 뷰티 문법

전자책의 뷰티 장은 스킨케어의 신뢰·피부 타입별 설명, 색조의 발색과 전후 증거, 기능성의 사전 검수 표현, 헤어/바디/향수의 상황·루틴을 강조한다. 이는 참고 업체의 제작 관점이며 시장 성과의 독립 측정이 아니다. 본 프로젝트는 이를 **구매 맥락 → 현재 구성/혜택 → 짧은 원본 증거 → 선택 기준/검증 FAQ → 조건 → 실제 상품 카드 행동**으로 바꾼다. [PDF 물리 pp.16–19](<팀 OneDrive AL라이브 폴더/AL라이브_전자책_44개 카테고리 완전정복 가이드.pdf>)

클렌징은 참고 PDF의 별도 뷰티 소분류가 아니므로 바닐라코 맞춤 확장이다. 구매 이유는 첫 구매·리필·용량 선택 등으로 설명하고, 밤→오일·세정 시연은 승인된 브랜드 원본을 짧게 연결한다. 모든 피부 타입 적합·저자극·블랙헤드 개선·이중 세안 불필요 같은 표현은 SEA SKU 승인 문구가 없으면 제외한다.

| 문법 영역 | AI가 맡는 설명 | 원본이 맡는 증거 | 대본 검수 경계 |
|---|---|---|---|
| 클렌징/기초 | 용량·구성·사용 순서·구매 목적·승인 FAQ | 제형·도포·세정 등 실제 촬영 | 개인 사용감·의학적 피부 진단 없음 |
| 쿠션/색조 | 판매 중인 셰이드·구성 비교·선택 방법 | 정확한 색상·피부톤의 원본 스와치/사용 컷 | AI 피부·새 before/after·발색 조작 없음 |
| 기능성 | 해당 국가에서 승인된 문구와 조건 | 승인 시험/자료의 정확한 맥락 | 치료·보장·효과 수치 창작 없음 |
| 선물/휴대/캠페인 | 실제 포장·용량·구성·기간·쿠폰 절차 | 패키지·실물 구성 | 미등록 미니·증정품·포장·가짜 품절/마감 없음 |

**권장 90초 판매 단위:** 0–6초 훅, 6–21초 혜택, 21–36초 구성 비교, 36–51초 원본 증거, 51–71초 쿠폰/조건, 71–83초 FAQ, 83–90초 CTA. [뷰티 문법](banila-shopee-ai-live_beauty-grammar_v1.md)의 배치와 동일하다. 한 6분 편집본은 독립적인 90초 단위 4개로 구성해 중간 진입자도 이해할 수 있게 한다. 회차 전체의 제안 편집 비율은 혜택·구성·거래 안내 60%, 원본 증거 20%, 사실 FAQ·브랜드 설명 20%다. 구간별 역할과 회차 전체 배분은 다른 측정 단위이며 모두 시험할 편집 목표다.

기본 영어는 금액·수량·유효 시간을 음성에 박지 않고 현재 상품 카드의 조건을 안내한다. 예: “Open the linked product card to review what's included and the current offer.” 이 문장도 실제 연결 카드가 있는 상황에서만 사용한다. 금액을 직접 말할 필요가 있으면 **오퍼 버전이 고정된 대본·음원·화면 쌍**으로 별도 생성하고 만료 뒤 재생을 막는다. 화면만 바꾸면서 낡은 음성의 가격을 유지하지 않는다.

“I tried this”, “I can feel the difference”, 방금 받은 댓글·사용자 이름·주문·품절 알림, 근거 없는 무료배송·할인 중복·재고 압박은 대본에서 금지한다. 사전 FAQ는 “A common question is…”처럼 일반 질문으로 설명하고 실제 댓글 응답인 척하지 않는다. 자세한 카테고리 변환과 승인 영어 예문은 [뷰티 문법](banila-shopee-ai-live_beauty-grammar_v1.md)에 둔다.

## 7. 콘텐츠 라이브러리와 24시간 편성

**MVP:** 6분 master 1편, 그 안의 독립적인 90초 판매 각도 4개, 교체 가능한 오프닝 4종. 음성·립싱크·사실 게이트를 통과한 뒤 사용 목적·배치 형식·예산을 확인하는 확대 체크포인트를 거쳐 6분 회차 4편으로 확장하고, 같은 체크포인트를 다시 거쳐 아래 12개 테마의 각 2개 서사를 제작한다. A/B는 배너만 바꾼 복제본이 아니라 구매 맥락·질문·선택 기준·증거 순서가 다른 버전이다.

**확대 체크포인트:** 4편·24편 대량 생성 전에 사용할 국가·계정·Live 또는 비Live placement, 필요한 화면 규격과 길이, 승인 조건, 채택 신규 호스트 분량 및 제작·검수 예산 상한을 기록한다. 공개 Live 형식이 미확정이면 6분 MVP까지만 검증하고, 별도로 허용된 활용 목적이 확정된 분량에 한해 확대한다. 24편 계획은 확보해야 할 콘텐츠 규모이지 정책·배치·예산이 없는 상태에서 모두 생성하라는 지시가 아니다.

조건이 충족되지 않는 테마는 미확인 상품을 만들어 채우지 않는다. 승인된 용량 선택·FAQ·카드 읽기 서사로 교체하고 테마 변경을 manifest에 기록한다. 성과가 낮은 서사는 더 많은 가격 압박 대신 훅·증거·조건 전달을 바꿔 시험한다.

24시간 로컬 리허설은 144분 블록 10개로 구성한다. 각 블록에서 입문→혜택→FAQ→비교 등의 순서를 바꾸고 같은 호스트 오프닝·SKU가 연속되지 않게 한다. 야간/낮의 소비자 행동 가설은 실제 국가 데이터가 생긴 뒤 검증하며, 지금 특정 시간의 매출 우위를 주장하지 않는다. 편성표에는 반복 회차 ID를 그대로 남겨 중복을 숨기지 않는다. 공개 허용 시간이 짧으면 허용 세션의 편성으로 잘라 운영자가 시작·종료·인계한다.

## 8. 데이터·제작·운영 구조

초기 구현은 기존 앱 전체를 재설계하는 작업이 아니다. 실제 코드 파일은 후속 `explore`가 좁게 매핑한 뒤 선정한다. 아래는 새 제작 자원의 계약과 운영 흐름이다.

```text
국가 SKU / 승인 오퍼 / 승인 클레임 / 권리 있는 원본
    → 대본 승인 → 영어 master audio → 짧은 립싱크 shot → 원본 편집
    → QA 고정본 + immutable manifest → 로컬 편성/리허설
    → [국가·계정별 공개 운영 게이트] → 허용된 감독 Live 경로
```

| registry / 자원 | 필수 필드 | 실패 시 동작 |
|---|---|---|
| SKU | country, seller, product/variant ID, 영문명, 용량, 판매 색상, card ID | 이름만으로 다른 국가·변형 매칭 금지 |
| offer | version, SKU, 통화·금액·단위, 구성/증정, 쿠폰 최소액·상한·적용 대상·중복 조건, 배송 조건, 재고, valid-from/until, 확인 시각·출처·책임자 | 미확인·만료·모순이면 거래 설명 차단 |
| claim | country, SKU, 승인 문구/번역, 근거 원본, 적용 조건, 승인자·기간 | 근거 없는 사실·효능 발화 차단 |
| media | 파일 hash, 정확한 SKU·색상, 지역/기간/placement, 초상·음성·음악 권리, 편집 허용 범위 | 미확보 또는 권리 범위 외 소스 배제 |
| scene/render | scene/narrative ID, script/offer/claim/media version, host/look/voice/model, source/audio/caption/render hash, payload, job/take ID, 채택 MP4, 리뷰 | 승인본과 다른 음원·자막·얼굴·오퍼를 혼합하지 않음 |

원본과 음원은 변경 없이 보관하고 새 take는 별도 기록한다. 공급사 job 재시도에는 같은 작업 idempotency key를 재사용하고 품질 개선용 새 take는 새 action으로 분리한다. 음성·자막·배너 숫자는 같은 승인 오퍼에서 각각 발음 문자열과 표시 문자열로 만들고 값 일치를 검사한다. 외부 서비스 업로드 전에 얼굴·음성 동의 및 실제 계약의 보관·학습·상업 사용 조건을 확인한다. [HeyGen 동의](https://developers.heygen.com/docs/avatar-consent), [Sync 데이터 보관 옵션](https://support.sync.so/articles/3861799718-what-are-your-data-retention-policies-and-can-we-opt-out-of-data-collection)

**Preflight는 큐에 넣을 때와 각 scene 재생 직전에 수행한다.** 국가·SKU·카드·오퍼·재고·권리·주장·만료를 대조하고, 오퍼 고정 발화는 `scene.end ≤ offer.valid_until`을 만족해야 한다. 데이터 신선도 허용치는 국가·운영방식별 SLA로 정하며, 증빙 없는 오래된 값은 최신값으로 취급하지 않는다. 오버레이·카드·음성은 같은 offer version으로 활성화한다. 실제 card pin·쿠폰 활성화 확인은 기본적으로 운영자가 수행하고 확인을 남긴다.

기본 큐 우선순위는 긴급 중단/정정 → 운영자 인계 → 검증된 거래 조건 변경 → 실제 FAQ → 일반 편성이다. FAQ는 같은 의도 질문을 합쳐 중복 응답을 줄이고 3분 cooldown을 초기 제안값으로 시험한다. 승인된 댓글 인터페이스가 없으면 운영자 입력을 사용한다. 사전 FAQ 재생은 실제 질문을 읽고 실시간 반응하는 것과 구분하며, 허용된 Live 모델의 상호작용 요건을 따로 충족한다.

**실패 제어:** 큐의 만료·모순 장면은 즉시 차단한다. 활성 가격·증정·재고 발화와 화면의 오류를 감지하면 오디오·위험 오버레이·장면을 안전한 중립 상태로 **감지 후 2초 이내 전환하는 로컬 목표**를 둔다. 원천 데이터의 갱신·사람 확인 지연은 별도 측정하며 모든 현지 오퍼 변화를 실시간 감지한다고 보장하지 않는다. 검증 가능한 일반 사실만 남기거나 사람에게 넘긴다. 오퍼와 무관한 evergreen 발화만 위험 화면 제거 후 다음 35초 이내 안전 경계까지 마칠 수 있다. 공개 자격·세션·인증 문제가 생기면 승인된 종료 경로를 사용하고 장시간 대기 화면으로 복구하지 않는다.

감시 항목은 현재 scene/offer/SKU/card, 확인 시각, 큐 길이·FAQ 중복, A/V timestamp, 검은 화면/무음, render 실패·생성 초수, 조작/중단/인계 로그다. 운영 인증·stream key·개인정보는 출력이나 콘텐츠에 넣지 않는다. 로컬 리허설에서 이미 통과한 파일에 별도로 `LIVE_ELIGIBLE(country, account, format, conditions, expiry)` 증빙이 있어야 공개 큐에 들어갈 수 있다.

## 10. 단계, 담당자, 비용과 검증

### 3–4주 초기 제작·검증 추정

필요 자원이 확보되고 제작 인력이 배정된 경우의 추정이며 납기 약속이 아니다. 플랫폼 승인 대기나 원본 권리 확보는 별도 소요일이다.

| 단계 | 시점 추정 | 산출물·담당 | 완료 조건 |
|---|---|---|---|
| 0. 거래/권리 기준 확정 | 1주차 전반 | 브랜드·현지 seller: SKU/offer/claim/media registry, 호스트 동의. 정책 담당: 국가·계정 조건 | 검증 샘플의 실제 사실·원본·권리 추적 가능. 공개 게이트는 별도 상태 |
| 1. 영어/립싱크 비교 | 1주차 후반 | 음성 디렉터·영상/기술·영어 QA: 6장면 두 후보 비교 | AC-LIP 통과 엔진/호스트/음성 및 실패 비용 기록 |
| 2. MVP/문법 검증 | 2주차 | 제작·브랜드 검수: 6분 1편 → 품질・배치・예산 체크포인트 통과 시 4편 | 중간 진입 이해, 승인 원본, 상품 카드/오퍼 일치 |
| 3. 라이브러리/운영 검증 | 3–4주차 | 편집·기술·QA: 확대 체크포인트 통과 후 24편, registry·manifest·큐·장애 제어, 24h 로컬 로그 | AC-FACT/AC-SOAK 통과, 결함 수정·재시험 |
| 4. 허용된 공개 파일럿 | 별도 게이트 충족 이후 | 현지 seller·운영자: 허용 형식/시간의 감독 방송 | AC-LIVE 및 별도 realtime 품질 조건. 미허용 시 비Live/사람 진행 경로 |

사업 책임자는 상품·쿠폰·배송·재고 기준을 소유하고 변경을 승인한다. 브랜드/컴플라이언스는 주장·번역·원본 권리를, 영어 디렉터는 발화·발음을, 기술 담당은 manifest/큐/감시를, 운영자는 실제 Shopee 거래 행동·중단·교대를 책임진다. 승인자와 담당자 실명은 실제 프로젝트 착수 시 기입한다.

### 비용 산식

`S`는 **최종 채택된 새 AI 진행자 렌더 초수**다. 회차 길이, 원본 삽입 시간, 같은 파일의 24시간 재생 시간과 구분해 manifest에서 합산한다. `r = 총 유료 생성 초수 / 최종 채택 초수`를 실험에서 측정한다.

```text
렌더 비용 = S × r × 엔진 초당 단가
총비용 = 렌더 + 영어 녹음/TTS + 호스트 원본/동의 제작
       + 원본 증거·권리 확인 + 편집/영어/브랜드 QA
       + subscription/인프라 + 현지 감독·콘솔 운영 인력 + 세금
```

공식 자료의 2026-10-02 확인 단가는 HeyGen IV Photo $2.31/분, IV Digital Twin/Studio $4.83/분, V Digital Twin $7.20/분이다. Sync Creator 25fps 기준 lipsync-2-pro $0.08325/초, sync-3 $0.13340/초이며 subscription $19/월이 별도다. 플랜·fps·해상도·계정·계약·청구 조건을 제작 전에 다시 확인한다. [HeyGen 최신 API 가격](https://help.heygen.com/en/articles/10060327-heygen-api-pricing-explained), [Sync 가격](https://sync.so/pricing)

`r=1.0/1.3/1.6`은 예산 민감도 가정으로만 비교한다. 원본/호스트 분량과 QA 인력, 공개 운영 시간·형식이 미정이므로 총액을 확정하지 않는다. 반복 재생에 매번 신규 생성비가 붙는다고 계산하지 않는다.

Unit은 offer 유효창·정확한 SKU 결합·숫자 문자열·claim/media 권리·scene 전이·FAQ coalescing/cooldown을 검사한다. Integration은 동일 master audio/hash, 공급사 재시도·callback·실패, 자막/음성/오퍼 버전의 결합, 실제 승인 데이터 변경을 검사한다. E2E는 승인 입력에서 master/렌더/편집/카드 preflight/로컬 재생까지 검증하고 거래 변경·운영자 인계·세션 종료를 주입한다. Observability는 상태·음성/영상 timestamp·오퍼 수명·black/silence·복구 시간·생성비 집계와 로그의 비밀정보 미노출을 확인한다. 세부 fixture, 판독 표본, 결과 파일은 [검증 명세](banila-shopee-ai-live_test-spec_v1.md)에서 관리한다.

실제 공개 파일럿에서는 유지 시청·상품 카드 클릭·쿠폰 이용·구매·취소/문의·운영자 개입을 가능한 승인 분석 범위에서 수집한다. 수치 목표는 현지 기존 방송 baseline이 생긴 뒤 정한다. 리허설이나 업체 소개로 매출 상승률을 예측하지 않는다.

## 11. ADR: 이번 계획의 결정 기록

- **Decision:** audio-first 영어 진행 콘텐츠를 짧은 shot으로 생산하고 원본 증거를 편집한다. HeyGen/Sync 비교 후 엔진을 채택한다. 24시간 로컬 리허설과 공개 Live 권한은 별도 관리한다.
- **Drivers:** 영어/입 자연스러움 최우선, 오퍼 변경 정확성, 시장별 허용 운영.
- **Alternatives considered:** hosted avatar, 원본 진행자+Sync 자체 제작 통제, 실시간 사람/승인 AI. 장편 한 번 생성·AI 제품 시연·미승인 자동 거래 조작·초기 자체 모델 구축은 요구/근거/권한을 충족하지 못해 제외했다.
- **Why chosen:** 같은 음원으로 품질을 비교하고 오류 구간만 교체할 수 있다. 변동 거래 사실과 고정 발화를 관리하며 브랜드 원본을 증거로 보존한다. 공개 정책이 바뀌어도 제작 자산을 활용할 수 있다.
- **Consequences:** 원본·권리·영어 QA와 감독 운영이 필요하다. 24편은 24시간 신규 분량이 아니며, offline 품질 통과가 realtime 품질이나 Shopee 승인을 보장하지 않는다.
- **Follow-ups:** 첫 국가·계정, 현지 SKU/offer, 원본 권리/주장 승인, 호스트/음성, 제작 예산, 공개 AI/세션 조건을 확정한다. 단계별 결과에 따라 분량·엔진·방송 형식을 수정한다.

## 12. 구현 인계 부록: 역할과 사용 가능한 실행 경로

현재 계획은 실행 모드를 켜지 않는다. 알려진 native 역할은 `planner`, `researcher`, `dependency-expert`, `explore`, `executor`, `designer`, `test-engineer`, `verifier`, `architect`, `critic`이며 prompt는 `~/.codex/prompts/`에서 AGENTS.md 아래 로드한다. 현재 세션의 후속은 native agents가 기본이다. 정책/원본 확보·registry 설계는 병렬, 영어 승인→렌더→편집→QA는 순차로 진행하고 공유 manifest writer는 1명으로 둔다.

| 경로 | 역할·규모 / 권장 reasoning | 검증 |
|---|---|---|
| 단일 책임 완료 루프 | executor 1명 medium/high + 필요 시 test-engineer/verifier, 정책 researcher | MVP와 실패 제어를 검증 명세로 확인 |
| 병렬 구현 | executor·designer·researcher·test-engineer 각 1명, 독립 architect/critic high | 통합 registry/manifest·benchmark·QA·모든 실패 주입·24h 로그를 verifier가 확인 |

`$ralph`, `$team`, `omx team`은 **실제 OMX CLI/runtime에서만** 사용한다. 지시 예: `$team "이 PRD와 test-spec 기준 데이터·콘텐츠·QA 실행 및 증거 통합"`, `$ralph "이 PRD와 test-spec 기준 MVP 완성 및 실패 경로 검증"`. `omx team` 인자는 설치 버전 도움말로 확인하고 현재 활성화하지 않는다. Team은 통합 증거를 남겨 종료하며, 필요한 후속 Ralph는 실패 기준을 수정·재검증한다. PRD와 test-spec이 먼저 있어야 한다.

목표 모드가 설치·호출 가능하고 실행이 요청되면 `$ultragoal`은 일반 완료 추적, `$autoresearch-goal`은 정책 연구, `$performance-goal`은 비용·지연 최적화에 고려한다. Team 결합 시 leader가 목표 ledger를 소유하고 Team이 증거를 반환한다. 현재 goal이나 유료 생성을 시작하지 않는다. Architect→Critic 순차 검토와 문법/검증 명세 정합성을 마치면 계획을 종료하고 root가 승인본을 `DOCS/plan/banila-shopee-ai-live_plan_v1.md`로 반영한다.
